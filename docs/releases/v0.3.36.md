# v0.3.36 — durable serial campaign continuation

This release turns the explicit bounded campaign contract into an opt-in
foreground controller. A single invocation resumes permitted active work or
pending managed cleanup first, then advances through eligible task IDs in the
contract's declared order. Existing task, workspace, completion and release
records remain authoritative; no parallel builder or second task queue is
introduced.

The controller freezes the contract revision and digest, stores an immutable
snapshot, binds one outside-repository workspace root, and checkpoints
cumulative active wall time, execution attempts and unique completed tasks.
Resume rejects mandate, snapshot, workspace and accounting drift. A crash after
authoritative managed completion is reconciled before new work is selected.

Safety and authority remain fail-closed. Task-local blockers can be skipped for
independent permitted work, while foreign active state, unsafe bindings and
unknown external effects stop the run. Release profiles must be campaign-
authorized and deployment permission cannot expand to a different configured
target. An empty eligible set reports `goal_verified: false`; goal auditing is
still a separate lifecycle step.

The existing template v0.3.17 commit remains the immutable compatibility
baseline. Template onboarding for this campaign behavior remains owned by the
separate `autonomy-template-01` task.
