# v0.3.48 — Serial task delivery and durable progress

“Go tot alle taken klaar” freezes the existing unfinished task set, including
blocked tasks. New taskwise campaigns have no implicit five-task/two-hour ceiling;
explicit budgets and restrictions remain binding. Every deliverable task passes verification,
review, authorized publication, configured deployment and closure readback before
the next task starts. Concretely blocked tasks remain visible while independent
work can continue. Existing run authority is not silently broadened.

Content-bound milestone proof distinguishes results from activity. Necessary
repairs and future task amendments remain linked to original outcomes. Current
resume context comes from canonical records, live ownership, source revisions and
valid proofs. Completed work and confirmed external effects survive a new session.

The progress contract includes stable event IDs, durable ordered acknowledgments,
a local reference adapter and an independently supervised 300-second heartbeat.
An unavailable transport prevents an unattended run; failed delivery holds the
next task. See [adapter setup](../progress-delivery.md). The local reference is not
a production chat connection and must not be reported as live user-chat rollout.

An effectless failed release can safely surrender its publication reservation
without losing candidate bytes or proof. A suspended candidate cannot publish or
resume automatically: it requires explicit reconciliation to a fresh candidate.
Published effects are never suspended or repeated by this mechanism.

The practical test uses ten real temporary task workspaces, a bare Git remote,
per-task tags, deployments and portable closure readback. It interrupts the fifth
done-message acknowledgement and resumes from a fresh process without repeating
valid work. Separate fault scenarios preserve blocked tasks while delivering
independent work. No GitHub Actions are used.

Rollback is an explicit consumer pin to immutable v0.3.47. Preserve newer progress
and suspension records as evidence; an older runtime must not reinterpret a new
execution contract or suspended publication as permission to run. Migrate an
existing taskwise campaign's progress transport through an explicit journaled
revision. Other consumers retain their pins until their normal update.

The designated real consumer/chat pilot is a separate rollout gate. Do not mark
the implementation assignment fully delivered until that connected proof exists.
