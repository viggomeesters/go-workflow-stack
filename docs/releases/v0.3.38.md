# v0.3.38 — grounded outcome behavior review

This release makes behavioral completion review explicit and content-bound. A fresh
critic context carries the original requested outcomes, exact governing product
goals, and only the architecture references made applicable by the task. Every
reference explains why it applies; tiny unrelated work acquires neither architecture
ceremony nor automatic visual-proof requirements.

Tasks adopting `behavior_review_version: 1` require a structured review for every
R#. Passed outcomes cite current hashed source, test, runtime, browser, visual or
audio evidence bound to the task, requirement, candidate and context. Preparation
documents, unrelated green checks, captures from another candidate and unreproduced
fix claims cannot substitute for delivered behavior.

Blocked reviews carry bounded repair actions inside the original scope and declared
checks while preserving the acceptance digest. Pre-publication review can leave
controller-owned release receipts pending; the existing final release gate still
requires tag, push, publication and remote readback.

Historical reviews remain readable through explicit adoption. The existing template
v0.3.17 commit remains the immutable compatibility baseline; template onboarding is
owned by the separate `autonomy-template-01` task.
