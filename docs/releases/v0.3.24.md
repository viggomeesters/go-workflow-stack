# v0.3.24 — explicit lifecycle adoption and preserved intake provenance

Projects can deliberately adopt lifecycle settings separately from a runtime pin
or legacy schema update. Preview reports eligible open tasks and preserved history;
apply requires a quiescent repository, stores exact state first and supports
explicit resume or rollback. Interrupted adoption blocks new work. Changed task
history and stale stack-update plans are preserved instead of overwritten.

Configured init/adopt/spike and ordinary task, intent, brief, recommendation and
follow-up intake retain model/effort, workspace, release and phase contracts.
New acceptance coverage stays pending. Existing overrides and named profiles stay
intact; a changed profile needs a new name. No historic task is reexecuted, no proof
is invented and configuration grants no execution or publication/deployment rights.

Export/import preserves full project/task contract and provenance records in a
checksummed review section. References remain references: external proof files,
Git objects and active runtime contents are not an executable transfer package.
Local skill and operator documentation describe released behavior and selective
legacy reuse, without restoring a vault writer or installing global skills.

Verification covers crash/resume/rollback, drift, historical bytes, every intake
path, full publication/deployment configuration preservation, schema roundtrips and
malformed input. No real model call, deployment or GitHub Actions is required by
these fixtures. Release validation uses the existing local Linux and distribution
gates with immutable template pairing.

Rollback: use a preserved migration journal only while its task inventory and
snapshots still match. Otherwise reconcile explicitly; reverting runtime product
code requires a new corrective release, preserving immutable published tags.
