# v0.3.31 — guided lifecycle onboarding

The internal `onboarding plan` command detects project version sources, current
branch, remote names and candidate checks without writing or executing them.
Explicit answers produce validated lifecycle settings and an execution brief.
Version/changelog paths are included in the first task's scope. Models, publisher,
checks and deployment policy remain deliberate inputs; no run authority is inferred.

Existing scaffold, migration, intake and native task execution paths are reused.
Tests prove generated settings and intake complete a first local Git release,
with pending outcomes, real verification/critic/readback and separate worktree
cleanup. The agent in this test is a deterministic native CLI double, not a live
model claim. Historical state and linked inputs remain preserved or rejected.

Verification: 33 onboarding/migration cases; the mandatory compatibility suite now
includes 14 onboarding cases. Candidate and exact-tag Linux distribution gates
use immutable template v0.3.16. The template's guided user flow follows separately.
