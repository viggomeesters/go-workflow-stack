# v0.3.45 — task-bound repository context

Tasks can now opt into a strict `repository_context` contract that names stable
repository-map nodes, adds bounded discovery queries, chooses dependency depth
and test inclusion, and fixes node/edge budgets.

The runtime resolves the contract only against a fresh local graph. Direct
semantic nodes are mandatory; deterministic traversal adds dependencies,
contained source, observed imports and linked tests until the declared budgets
are reached. Every selected source carries its exact hash. Build, critic and
repair receive this same bounded payload with explicit freshness and authority,
never the whole generated graph.

`task create --repository-context context.json` provides schema-backed
authoring. Missing maps, unknown node IDs, missing graphs and stale graphs fail
before dispatch. Existing tasks without the field retain their prior context
unchanged.
