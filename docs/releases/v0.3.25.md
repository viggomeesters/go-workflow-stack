# v0.3.25 — verified phase worker topology

Fresh native CLI workers remain the supported Go model-switching baseline. Build,
critic and repair use frozen profiles at phase boundaries in one owned worktree.
Repository context and run selection survive parent process exit. A different
critic profile does not change the build/repair profile or create another task.

This release captures official local Codex 0.153.4 protocol evidence and executable
fixture tests for phase transitions, canonical recovery, attribution and exclusive
writers. Persistent turn overrides exist in that protocol and persist to later
turns; they do not constitute an implemented Go adapter. Persistent-session and
subagent adapters are explicitly deferred without blocking the baseline.

No mid-turn switching, independent effective-model attestation or live model
execution is claimed by these fixtures. Live lifecycle proof remains abc-10.
See docs/worker-topologies.md for capability levels, limits and future adapter gates.

Verification: topology process tests, relevant existing model/context/workspace
regressions, ordinary-clone make check and Linux candidate/exact-tag distribution
gates. No GitHub Actions, global skill change or production deployment.

Rollback: use an earlier immutable release for a consumer pin, or publish a new
corrective release. Do not rewrite published tags or delete active workspace state.
