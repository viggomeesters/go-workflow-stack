# v0.3.37 — persistent campaign recovery supervision

This release makes bounded serial campaigns recoverable across controller
interruption without resetting their authority or budgets. The campaign state
now records controller identity, dispatch stage, a conservative active-wall
clock, frozen command/repair ceilings, and cumulative consumption. A successor
repeats the exact pending task only after proving the prior local controller is
dead; live local and unknown cross-host ownership fail closed.

Temporary provider failures use a durable exponential backoff capped at 60
seconds. The task's exact model and effort remain frozen throughout recovery,
so retry cannot silently fall back or escalate. Failed checks remain available
as managed evidence and bounded campaign feedback for a new worker or critic.

Repeated evidence-identical failures are classified as no-progress. The task is
isolated—active work moves to the canonical blocked queue with its checkpoint
and workspace intact—and only independently eligible work may continue. Pause,
drain, and cancel are explicit lock-protected boundary actions that dispatch no
new work and never signal an unverified process.

The existing template v0.3.17 commit remains the immutable compatibility
baseline. Template onboarding for these recovery controls remains owned by the
separate `autonomy-template-01` task.
