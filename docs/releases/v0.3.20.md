# v0.3.20 — verified lifecycle completion

Opted-in tasks can only finish or gain approval with executed verification,
explicit review and their required release proof bound to the same product
content. Failed push/readback restores active state; reporting excludes invalid
completion. The controller captures commands and full raw results with the shared
orphan-process guard. Read-only Git-tag and GitHub release profiles verify exact
annotated objects, commit content and remote branch ancestry.

Regressions cover manual and automatic bypasses, approval, code/evidence/remote
changes, failed real checks, missing profiles, requirement proof, and killed
collectors with live workers. Legacy unconfigured behavior and unmigrated history
remain explicit. Publication automation and deployment are subsequent tasks;
managed successful phases still return release_pending.

Same-agent critic statements and model identity are not independent attestations.
Keep canonical proof and workspaces for recovery. Do not downgrade opted-in tasks
to a runtime that lacks these completion gates.
