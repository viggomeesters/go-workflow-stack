# v0.3.30 — TOML publication version sources

Publication profiles now accept `format: toml` with an explicit dotted key such
as `project.version` or `tool.poetry.version`. Only the selected static semantic
version literal changes; surrounding bytes, comments, CRLF and other values are
preserved. Dynamic, missing, invalid and unsupported representations fail before
reservation or preparation writes. Project and onboarding schemas agree.

The existing owned-worktree publisher, verification, release readback and recovery
remain authoritative. Tests cover a real local Git release and a lost push
acknowledgement resumed without repeating the push, alongside text/JSON regressions.

Verification: 42 TOML/publication cases; mandatory compatibility phase includes
TOML tests. Candidate and exact-tag Linux distribution gates use immutable template
v0.3.16. No consumer, model defaults or deployment destination is changed.
