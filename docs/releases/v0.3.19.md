# v0.3.19 — managed phase resume

Explicit managed native tasks retain setup, build, individual verification,
critic and repair checkpoints across budget exhaustion and controller death.
Requested model profiles, context references, requirements and raw phase evidence
remain tied to the same task/run/workspace. A live controller or orphan worker
blocks takeover; standalone workspace mutations enforce the same guard.

Changed code or canonical instructions invalidate affected proof without
resetting files. Explicit local checkout relocation keeps a durable path map,
repairs Git metadata and can recover a crash during repair. External effect
intent/readback interfaces retain unconfirmed publication state; cleanup recovery
only removes already delivered, verified workspaces. Publication itself remains
subsequent ABC work, so successful phases return release_pending with an active
task. Legacy unopted execution is unchanged.

Verification covers real Git/process fixtures, orphan/live-owner refusal,
interrupted preparation/relocation, code/model drift, effect readback, cleanup,
model/context/workspace regressions, smoke, make check, template/distribution
pairing and annotated-tag validation. Fixtures do not claim live model quality
or independent model identity.

Stop workers before rollback. Preserve canonical run/checkpoint/context data and
worktrees; older runtimes cannot infer a safe phase from these new checkpoints.
Use the previous immutable version only for its supported legacy execution.
