# v0.3.23 — explicit deployment and live-version proof

An explicitly configured task release can package and deploy through trusted
command adapters, then require authoritative readback of the target, commit,
version, operation identity and optional artifact hash before finishing.
Deployment needs separate run authorization; model or push settings do not grant it.

The controller persists intent and uses the adapter's stable idempotency key.
Accepted-but-not-live and unknown responses keep the task pending. Resume queries
the same operation before another effect; partial local packages are preserved and
rebuilt into fresh storage. No automatic rollback is inferred.

Final live proof includes the executed observer output and binds the released
profile and version. Finish and approval query the target again; historical clones
validate saved proof without requiring an old service version to remain online.
Explicit no-deployment profiles and legacy release-only profiles stay supported.

Local Git/process fixtures verify full lifecycle, lost acknowledgements, incorrect
live identity, remote package changes, packaging interruption, budgets and ordinary
clone history. No real deployment provider or production environment is configured.
Adapters must query authoritative target state and honor their idempotency contract.
GitHub Actions are not used. Cross-host recovery remains separate work.

Rollback: revert this release's product changes and release a new corrected version;
preserve immutable published tags and any pending deployment records for recovery.
