# v0.3.32 — immutable stack/template pairing catalog

A single manifest replaces repeated historical version branches in the release
gate. All 23 earlier recorded template hashes are preserved, a current baseline
is added, and earlier releases without a recorded baseline remain explicitly
unpaired. No historical tags or evidence are invented or rewritten.

Internal pairing commands validate commit/tag identity, check the starter's
current pin and generate a deterministic README block with its exact stack SHA.
The baseline remains template v0.3.16; the subsequent starter release adopts this
stack separately, avoiding mutually dependent future commit hashes.

Verification covers malformed/missing/duplicate mappings, changed baselines,
contradictory pins/docs and the old immutable mapping regression. Linux adds a
dirty-module injection regression. The full manifest is validated only from the
checked release payload; standalone installation must retain the same catalog.
Candidate and exact-tag gates retain the full compatibility and smoke suites.

During final verification, a macOS network hostname change exposed a completed
capture ownership bug. A capture with phase complete, no in-flight operation and
no worker group now releases its liveness claim without querying its old hostname.
Its evidence remains untouched; incomplete or potentially live processes still
fail closed. Regression coverage includes real verification-to-critic handoff and
the existing cross-host active-owner rejection.
