# v0.3.49 — Live terminal progress

A configured Go run now opens a live terminal window beside the chat. It displays
existing task IDs, phase transitions, results and independently generated
five-minute heartbeats, including when the model/controller is waiting.

Select the terminal once with `./go progress terminal . --enable`. New campaigns
freeze the resulting transport; saved campaigns retain their existing settings.
macOS uses Terminal.app; graphical Linux uses an available x-terminal-emulator.
Missing launch support fails explicitly. An already attached TTY can follow a
campaign with `./go progress watch . --campaign <id>`.

Delivery is acknowledged only after the viewer prints and flushes the exact
outbox event to an actual TTY. Closing the viewer leaves unrendered events pending
and prevents the next task from starting. Reopening visibly replays stored
history without rerunning tasks. Stable receipts survive retries; a crash between
printing and recording may repeat a line. Terminal output is not chat delivery or
human reading approval.

No task queue, model runner or publication authority is added. Old run records,
consumer pins and the immutable template baseline remain compatible. Rollback by
pinning v0.3.48 after explicitly restoring the consumer's previous progress
transport; preserve newer evidence and do not reinterpret new transport settings
as permission for an older runtime.

The same messages are persisted as a readable per-campaign `.log`, including
while the viewer is closed. The terminal reads that verified projection; manual
`tail -F` remains available. Canonical JSON retains all task/event authority.
