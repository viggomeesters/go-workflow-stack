# v0.3.17 — owned task workspaces

Tasks can opt into one explicit branch/worktree, bound to the canonical task,
owner, run and base revision. CLI reads use the canonical control state; worker
mutations are limited to owned outcomes. Common-directory process locks protect
creation and execution. Full-diff scope checks gate staging and integration.

Integration is an exclusive API boundary, with exact revisions and ancestry
proof. Cleanup requires approved completion and the configured release receipt,
refuses dirty/ignored files, and retains work on failure without republishing.
The registry schema, real Git fixtures and docs/task-workspaces.md describe the
contract. This release exposes the primitives; automatic fresh-worker/resume and
publisher wiring remain in the following ABC tasks.

Verification: task workspace fixtures, model/contracts/architecture regressions,
smoke tests, make check, template pairing, distribution and annotated-tag gate.
Existing unregistered worktrees retain legacy behavior. Rollback requires an
older immutable stack pin after stopping managed workers; preserve registries,
markers and worktree contents. Do not run old queue writers inside managed
worktrees or remove state to bypass ownership.
