# v0.3.34 — bounded autonomy campaign contracts

This release introduces the versioned `go-workflow.campaign-contract.v1`
boundary for serial autonomous runs. A campaign revision binds original intent,
adopted goal outcomes, existing task R# references, accepted architecture
decisions, an explicit task allowlist, model profiles, cumulative command/time
budgets, bounded research and repair, separate release/deployment grants, and
mandatory stop conditions.

Validation is deliberately read-only. It cannot grant authority, dispatch a
worker, duplicate task or outcome state, infer production permission, or turn
an empty eligible queue into goal completion. Unresolved material decisions
remain visible while independent allowed work can still be distinguished.

The release also isolates managed verification in an unregistered disposable
checkout whose tracked-content and changed-file hashes match the owned
candidate. Repository-wide checks may create their own fixtures without
weakening the registered-worker mutation guard. Focused regressions, the local
smoke gate, architecture conformance, and a fresh semantic critic cover the
change.

The existing template v0.3.17 commit remains the immutable compatibility
baseline. Applying the new autonomy contract to template onboarding is owned by
the separate `autonomy-template-01` task and is not claimed by this release.
